# フェーズ2-1: 顧客管理 実装計画

## Context

フェーズ1（土台構築）が完了し、認証・権限・レイアウト・バリデーション・テストの基盤が整った状態。
フェーズ2-1として顧客管理のCRUD機能を実装する。モックアップ（`_archive/mockup/app/admin/customers/`）のUIを踏襲し、設計案（`docs/nextjs設計案/04-Next.jsベストプラクティス設計案_20260128.md`）のパターンに従う。

### 設計判断
- **姓名フィールド**: DBを `name` → `firstName`/`lastName`、`nameKana` → `firstNameKana`/`lastNameKana` にマイグレーション
- **フィルタリング**: クライアントサイド（初期表示で全件取得、useMemoで絞り込み）
- **レビューサイクル**: 各ステップで「実装 → テスト → Codexレビュー → 修正」を実施

## ステップ1: DBマイグレーション + バリデーション更新

### 1-1. Prismaスキーマ変更
**対象**: `prisma/schema.prisma`

Customerモデルの変更:
```
name        → firstName (VarChar(100)) + lastName (VarChar(100))
nameKana    → firstNameKana (VarChar(100)) + lastNameKana (VarChar(100))
```
※ VarCharの長さは元の100を維持（50に縮小すると将来データ移行時に切り詰めリスクあり）

### 1-2. DBリセット（データ未投入のため）
```bash
npx prisma db push --force-reset
npm run db:generate
npm run db:seed
```

### 1-3. バリデーション更新
**対象**: `lib/validations/customer.ts`

- `name` → `firstName` + `lastName` に変更
- `nameKana` → `firstNameKana` + `lastNameKana` に変更
- コミュニティ詳細のバリデーションスキーマ（`customerCommunitySchema`）を追加
- `customerFormSchema` = customerSchema + communities 配列

### 1-4. 定数ファイル確認
**対象**: `lib/constants/customer.ts` — 変更不要（既に充実）

### 1-5. Seed更新
**対象**: `prisma/seed.ts` — 顧客シードデータがあれば firstName/lastName に対応

### 1-6. テスト更新
**対象**: `__tests__/lib/validations/customer.test.ts`

**customerSchema テスト（既存を更新）**
- 正常系: 必須項目のみ（firstName, lastName, email）
- 正常系: 全項目入力（全フィールド指定）
- 異常系: firstName が空 → エラー
- 異常系: lastName が空 → エラー

**customerFormSchema テスト（新規追加）**

## ステップ2: Repository層

### 作成ファイル
**`lib/repositories/customer.repository.ts`**

### 関数一覧

| 関数 | 用途 |
|------|------|
| `findAll(scopedCommunityIds, isSuper, filters?)` | 一覧取得（スコープ+フィルタ、deletedAt=null） |
| `findById(id)` | 詳細取得（communities + rsvps include） |
| `create(data)` | 新規作成（Customer + CustomerCommunity を $transaction） |
| `update(id, data)` | 更新（CustomerCommunity の差分更新を $transaction） |
| `softDelete(id)` | 論理削除（deletedAt 設定） |
| `existsByEmail(email, idToExclude?)` | メール重複チェック |

### 型定義（同ファイル内）
- `CustomerWithCommunities` — Customer + customerCommunities（community含む）
- `CustomerDetail` — 上記 + rsvps（event含む）
- `CustomerListFilters` — keyword, communityIds, memberCategories, auditMemberTypes, premiumOnly, includeFormerMembers, includeNonMember

### フィルタ仕様の定義
- **includeFormerMembers**: 「全コミュニティで resignedAt が設定済み」の顧客を含むかどうか（1つでも有効なコミュニティがあれば現役扱い）
- **premiumOnly**: ベンチャー監査役の会の CustomerCommunity で auditMemberPremium=true の顧客のみ
- **includeNonMember**: どのコミュニティにも所属していない顧客を含むか。community_admin の場合はサーバー側で強制 false

### スコープ強制ルール
- `findAll` は必ず scopedCommunityIds でフィルタし、community_admin にスコープ外データを返さない
- community_admin の場合、includeNonMember は強制 false（サーバー側で上書き）

### 再利用する既存コード
- `lib/prisma.ts` — PrismaClient シングルトン
- `lib/auth/permissions.ts` — `AdminForPermission`, `getScopedCommunityIds`, `canAccessCustomer`

### テスト
**`__tests__/helpers/mock-prisma.ts`** にメソッド追加:
- `customer.findMany`, `customer.findUnique`, `customer.create`, `customer.update`
- `customerCommunity.findMany`, `customerCommunity.deleteMany`, `customerCommunity.createMany`
- `prisma.$transaction`

**`__tests__/lib/repositories/customer.repository.test.ts`**

**findAll テスト**
- super管理者: 全コミュニティの顧客を取得（deletedAt=null のみ）
- community_admin: scopedCommunityIds 内の顧客のみ取得
- キーワード検索: firstName/lastName/company/email に部分一致
- includeNonMember=false: コミュニティ未所属の顧客を除外
- includeFormerMembers=true: resignedAt ありの顧客も含む
- memberCategories フィルタ: member/sponsor/observer で絞り込み
- auditMemberTypes フィルタ: regular/online で絞り込み
- premiumOnly: auditMemberPremium=true の顧客のみ
- 複合フィルタ: 複数条件の組み合わせ
- 空結果: 条件に一致する顧客なし → 空配列

**findById テスト**
- 正常系: 存在する顧客 → Customer + customerCommunities + rsvps を返す
- 異常系: 存在しないID → null
- 正常系: deletedAt ありの顧客 → null（論理削除済みは取得しない）

**create テスト**

**softDelete テスト**

**existsByEmail テスト**

## ステップ3: Server Actions

### 作成ファイル
**`lib/actions/customer.actions.ts`**

### 関数一覧

| 関数 | 用途 |
|------|------|
| `createCustomerAction(formData)` | 新規作成（認証→権限→バリデーション→スコープ検証→重複チェック→作成→revalidate→redirect） |
| `updateCustomerAction(id, formData)` | 更新（認証→canAccessCustomer→バリデーション→スコープ検証→重複チェック→更新→revalidate→redirect） |
| `deleteCustomerAction(id)` | 論理削除（認証→canAccessCustomer→softDelete→revalidate→redirect） |
| `exportCustomersAction(filters)` | CSV生成（認証→スコープ取得→データ取得→CSV文字列生成→返却） |

### 共通ヘルパー（Actions内）
- `getAdminForPermission(adminId)` — セッションのuser.idからAdminForPermissionを構築

### 戻り値型
```typescript
// 成功時は redirect() で例外が投げられるため、ActionResult は失敗時のみ返される
type ActionResult = { error?: string; fieldErrors?: Record<string, string[]> }
```

### スコープ検証（重要）
- `createCustomerAction`: community_admin が指定した communityIds が全て scopedCommunityIds 内か検証
- `updateCustomerAction`: 上記に加え、canAccessCustomer で既存顧客へのアクセス権確認
- メール重複チェック: `existsByEmail` に加え、Prisma の unique 制約違反（P2002）を catch してユーザーフレンドリーなエラーを返す

### 再利用する既存コード
- `lib/auth/permissions.ts` — `requireAuth`, `canAccessCustomer`, `getScopedCommunityIds`
- `lib/validations/customer.ts` — `customerFormSchema`
- `lib/repositories/customer.repository.ts` — 全関数

### テスト
**`__tests__/lib/actions/customer.actions.test.ts`**

モック対象: `requireAuth`, `canAccessCustomer`, `getScopedCommunityIds`, `customer.repository`, `revalidatePath`, `redirect`

**createCustomerAction テスト**

- 異常系: 未認証（requireAuth が例外）→ エラー返却
- 異常系: バリデーションエラー（firstName 空）→ fieldErrors 返却

- 異常系: メールアドレス重複（Prisma P2002 unique制約違反）→ error 返却
- 異常系: community_admin がスコープ外コミュニティIDを指定 → エラー

## 検証方法

### 各ステップ共通
1. `npm run build` — ビルド通過確認
2. `npm test` — 全テスト通過確認
3. `/review-by-agent` — Codexによるレビュー

### 機能テスト（ステップ5以降）
1. ブラウザで `http://localhost:3000/admin/customers` にアクセス
2. super管理者でログイン → 全顧客表示、全フィルタ表示を確認
3. community_admin でログイン → スコープ内顧客のみ表示、非会員フィルタ非表示を確認
4. 新規登録 → コミュニティ選択で条件付きパネル表示 → 登録成功 → 一覧に反映
5. 詳細表示 → 会員情報、プロフィール、イベント履歴が正しく表示
6. 編集 → 既存データがプリフィル → 更新成功
7. 削除 → 確認ダイアログ → 削除後一覧から消える
8. CSVダウンロード → ファイルが正しく生成、Excelで開ける
9. 権限外の顧客IDに直接アクセス → 404表示
