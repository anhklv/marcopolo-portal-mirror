## 変更2: 管理者切り替えServer Action

**新規ファイル**: `lib/actions/debug.ts`

### 方針: 固定パスワードでloginActionを呼び直す（案B）

authorize関数を一切変更せず、`switchDebugAdmin` Server Action内で既存の `loginAction(email, "rara6y")` を呼ぶ。固定パスワードはServer Action内に閉じ込めるため、クライアントに露出しない。

### 実装する関数:
1. **`getDebugAdminList()`** - 管理者一覧を返す（DEBUGモード時のみ、それ以外は空配列）
   - Prisma経由でAdmin + AdminCommunity + Community をJOIN取得
   - 返却型: `{ id, email, firstName, lastName, role, communities: {code, name}[] }[]`

2. **`switchDebugAdmin(email: string)`** - 指定メールの管理者に切り替え
   - `process.env.DEBUG_ADMIN_PANEL !== "true"` なら即エラー返却
   - 内部で `loginAction(email, "rara6y")` を呼ぶ
   - 返却型: `loginAction` と同じ `{ success, error }`

## 変更3: 管理者切り替えUIコンポーネント

**新規ファイル**: `components/debug/admin-switcher.tsx`

- サイドバーフッターのドロップダウンメニュー内に「管理者切り替え」項目を追加
- クリックでDialog（既存の `components/ui/dialog.tsx` を利用）を開く
- Dialog内に管理者一覧をリスト表示（メール、名前、ロール、所属コミュニティ）
- 現在ログイン中のアカウントはハイライト＋選択不可
- 選択するとswitchDebugAdmin → router.refresh() で画面更新

### DropdownMenu + Dialog の注意点
radix-uiではDropdownMenu内からDialogを開くと、DropdownMenuの閉じタイミングとDialogのfocus管理が干渉する場合がある。`DropdownMenuItem` に `onSelect={(e) => e.preventDefault()}` を設定し、Dialogの開閉を手動制御する。

## 検証手順

1. `npx prisma db reset` でDB再作成 → 5アカウントが正しく作成されること
2. 各アカウント（admin, kansa, naikan, ai, all）で個別にログイン成功すること
3. ログインフォームで各アカウントクリック → メール・パスワードが自動入力されること
4. DEBUGモードON時、サイドバーフッターに「管理者切り替え」が表示されること
5. 管理者切り替えで別アカウントに切り替え → サイドバーの名前・メール・ロールが更新されること
6. DEBUGモードOFF時、「管理者切り替え」メニューが一切表示されないこと
