# フェーズ1: 土台構築 - 実装計画

## 概要

フェーズ0（設計）完了済みの状態から、アプリケーションの土台を構築する。

## 決定事項（ヒアリング結果）

- **スコープ**: UIコンポーネント / NextAuth.js / レイアウト / Vitest すべて対象
- **認証方式**: JWT セッション（Auth.js v5 Credentials Provider の公式推奨）
- **UI方針**: mockup からコピー・改善。shadcn/ui スタイルは `default` を維持
- **テスト範囲**: 権限チェックヘルパー + Zod バリデーション中心

### Step 5: NextAuth.js セットアップ（JWT認証）

**設計ポイント:**
- Auth.js v5（next-auth@beta）を使用
- Credentials Provider（メール + パスワード）
- JWT にロール・管理者情報を含める（DBアクセス不要でセッション確認可能）
- Edge Runtime 対応のため `auth.config.ts`（軽量設定）と `auth.ts`（フル設定）を分離
- **JWT maxAge を短め（例: 1時間）に設定** し、ロール変更時のリスクを軽減する。将来的に管理者数が増えた場合は tokenVersion 方式やDB照合方式を検討する
  - 管理者は少人数（〜10名程度）の運用想定のため、フェーズ1では短いmaxAge + 手動再ログインで十分

**新規作成:**
- `lib/auth/auth.config.ts` - Edge互換設定（callbacks: authorized, jwt, session）
- `lib/auth/auth.ts` - フル設定（Credentials Provider + bcrypt認証、maxAge設定）
- `lib/auth/types.ts` - NextAuth型拡張（User, Session, JWT にrole/firstName/lastName追加）
- `app/api/auth/[...nextauth]/route.ts` - Auth.js APIルートハンドラ
- `app/admin/login/page.tsx` - ログインページ（mockupベース、`useAuth()` → Server Action + `signIn()` に置換）
- `lib/actions/auth.ts` - ログイン用Server Action

**環境変数追加（.env）:**
```
AUTH_SECRET=<npx auth secret で生成>
DEBUG_ADMIN_PANEL=true
```

> `DEBUG_ADMIN_PANEL` はサーバーサイド専用（`NEXT_PUBLIC_` プレフィックスなし）。クライアントに露出させない。サイドバー等のClient Componentでは、Server Componentから props で渡す。

**シードデータ追加（`prisma/seed.ts`）:**
- テスト用super管理者（admin@example.com / password12345）
- テスト用community_admin（community@example.com / password12345）
- admin_communities の紐づけデータ

### Step 6: レイアウト・サイドバー + Middleware

**Middleware:**
- `middleware.ts`（プロジェクトルート）- `/admin/*` の認証・アクセス制御
  - 未認証 → `/admin/login` へリダイレクト
  - `/admin/login` で認証済み → `/admin` (ダッシュボード) へリダイレクト
  - `/admin/admins` で community_admin → 403
  - `/admin/sitemap`, `/admin/styleguide` で `DEBUG_ADMIN_PANEL !== 'true'` → 404（権限設計ドキュメント準拠）

**レイアウト構造（Route Groups使用）:**
```
app/admin/
  login/page.tsx              ← サイドバーなし
  (dashboard)/
    layout.tsx                ← サイドバー付きレイアウト（Server Component）
    page.tsx                  ← ダッシュボード（プレースホルダ）
    customers/（フェーズ2）
    events/（フェーズ2）
    admins/（フェーズ2）
    settings/password/（フェーズ2）
    sitemap/（フェーズ2）
    styleguide/（既存をRoute Group内に移動）
```

**新規作成:**
- `app/admin/(dashboard)/layout.tsx` - 認証済みレイアウト（`auth()` でセッション取得、サイドバー表示）
  - `DEBUG_ADMIN_PANEL` の値を取得し、props でサイドバーに渡す
- `app/admin/(dashboard)/page.tsx` - ダッシュボード（プレースホルダ）
- `components/layout/sidebar.tsx` - サイドバー（mockupベース、以下を変更）
  - `useAuth()` → props で admin 情報受取
  - `logout()` → `signOut()` に置換
  - 開発メニュー全体を props の `debugMode` で条件表示
  - 管理者切り替え機能はフェーズ1では一旦省略（DBからの管理者一覧取得が必要で、開発メニュー内に全管理者情報を露出させるリスクがあるため）

**更新:**
- `app/layout.tsx` - `lang="ja"` に変更、Toaster（sonner）追加

### Step 7: 権限チェックヘルパー + Zod バリデーション + テスト

**権限チェックヘルパー**（`lib/auth/permissions.ts`）:

| 関数 | 用途 |
|------|------|
| `getSession()` | セッション取得 |
| `requireAuth()` | 認証必須（未認証で例外） |
| `requireSuper()` | super権限必須 |
| `getScopedCommunityIds(admin)` | スコープ内コミュニティID取得（adminオブジェクトを受け取る。権限設計ドキュメント準拠） |
| `canAccessCustomer(admin, customerId)` | 顧客アクセス権判定 |
| `canAccessEvent(admin, eventId)` | イベントアクセス権判定 |
| `canManageSurvey(admin, eventId)` | アンケート操作権判定（スコープチェック + has_surveyチェック） |
| `checkEventStatus(event, requiredStatus)` | イベント状態の前提条件確認 |

> `getScopedCommunityIds` 等の引数は admin オブジェクト（{id, role, adminCommunities}）を受け取る設計に統一する。DB問い合わせの重複を避け、権限設計ドキュメントのシグネチャと整合させる。

**checkEventStatus の状態名:**
- ドキュメント（画面設計書）の状態名と整合させる
  - `receiving`（受付中）: 回答期限前 + 未停止
  - `waiting`（開催待ち）: 回答期限後〜開催日前
  - `closed`（終了）: 開催日後
  - `paused`（停止中）: isPaused=true

**Zodバリデーション:**
- `lib/validations/customer.ts` - 顧客登録・更新スキーマ
- `lib/validations/event.ts` - イベント作成・更新スキーマ
- `lib/validations/admin.ts` - 管理者登録・更新・パスワード変更スキーマ
- `lib/validations/login.ts` - ログインスキーマ

**テストファイル:**
- `__tests__/helpers/mock-prisma.ts` - Prismaモック
- `__tests__/lib/auth/permissions.test.ts` - 権限チェックテスト
  - `getScopedCommunityIds`: super→全ID / community_admin→紐づきIDのみ / 0件→空配列
  - `canAccessCustomer`: super→常にtrue / スコープ内→true / スコープ外→false / 非会員→false
  - `canAccessEvent`: super→常にtrue / スコープ内→true / スコープ外→false
  - `canManageSurvey`:
    - スコープ内 + has_survey=true → true
    - スコープ内 + has_survey=false → false（superでも）
    - **スコープ外 + has_survey=true → false**（community_adminのスコープ外操作を確実に拒否）
    - 存在しないイベント → false
  - `checkEventStatus`:
    - 回答期限前 + 未停止 → `receiving`
    - 回答期限後〜開催日前 → `waiting`
    - 開催日後 → `closed`
    - 停止中 → `paused`
  - `requireAuth` / `requireSuper`: 未認証→例外 / 権限不足→例外
- `__tests__/lib/validations/customer.test.ts` - 顧客バリデーション正常系・異常系
- `__tests__/lib/validations/event.test.ts` - イベントバリデーション
- `__tests__/lib/validations/admin.test.ts` - 管理者バリデーション（パスワード一致確認含む）
- `__tests__/lib/validations/login.test.ts` - ログインバリデーション

## 注意点

1. **radix-ui import**: プロダクトの `package.json` には `radix-ui` v1.4.3 が入っているが、mockup は `@radix-ui/react-*` 個別パッケージを使用。カスタムコンポーネントのimport文が動作するかビルドで確認し、問題がある場合のみ修正する
2. **shadcn/uiスタイル**: mockup (`new-york`) → プロダクト (`default`)。ベースコンポーネントは `npx shadcn@latest add` で再生成するため問題なし。カスタムコンポーネントはスタイル非依存のため影響なし
3. **Edge Runtime**: Middleware で Prisma は使えない。`auth.config.ts` を分離し、Middleware では JWT のみで認証判定する。`DEBUG_ADMIN_PANEL` の読み取りは `process.env` で可能（サーバーサイド環境変数）
4. **Prisma Client生成**: `npm run db:generate` を実行しないと型エラーになる
5. **JWT セッション無効化**: maxAge を短く（1時間程度）設定。管理者のロール変更時は再ログインが必要な旨をUIで案内する。フェーズ1では少人数運用のため十分
6. **Auth.js v5 はbeta**: APIが変更される可能性があるため、実装時に公式ドキュメントを確認する

## 検証方法

1. `npm run build` が成功すること
2. `npm run dev` でアプリが起動すること
3. `/admin/login` でログインフォームが表示されること
4. テスト用管理者でログインし、ダッシュボード（`/admin`）に遷移すること
5. サイドバーが正しく表示されること（メニュー、ログイン中表示、ログアウト）
6. 未認証で `/admin` にアクセスすると `/admin/login` にリダイレクトされること
7. community_admin で `/admin/admins` にアクセスすると 403 になること
8. `DEBUG_ADMIN_PANEL=false` の状態で `/admin/sitemap` にアクセスすると 404 になること
9. `npm run test:run` で全テストがパスすること
