# DB設計（2026/02/19）

## 概要

PostgreSQL 17 + Prisma でのデータベース設計

## 前提

| 項目 | 決定事項 |
|------|---------|
| RDBMS | PostgreSQL 17 |
| ORM | Prisma 7.3.0 |
| ID | 自動採番（autoincrement） |
| 削除方式 | 論理削除（deletedAt） ※イベント・顧客 |
| コミュニティ | マスターテーブル管理 |
| マスターデータ | 都道府県・上場区分・出身業種・入会資格・所属もマスターテーブル管理 |

## 旧版からの主な変更点（2026/02/05 → 2026/02/19）

1. **マスターテーブル正規化**
   - 都道府県・上場区分・出身業種・入会資格・所属を個別のマスターテーブルに分離
   - customers / customer_communities から文字列カラムを削除し、FK参照に変更

2. **customersテーブルの変更**
   - `name` → `last_name` + `first_name` に分割
   - `name_kana` → `last_name_kana` + `first_name_kana` に分割（任意項目化）
   - `prefecture` → `prefecture_id`（FK → prefectures）
   - `listing_category` → `listing_category_id`（FK → listing_categories）
   - `origin_industry`, `membership_qualification` を削除（customer_communitiesに移動）
   - `job_change_intent` を追加（JobChangeIntent enum）

3. **customer_communitiesテーブルの変更**
   - `affiliation` → `affiliation_id`（FK → affiliations）
   - `origin_industry_id` を追加（FK → origin_industries）
   - `membership_qualification_id` を追加（FK → membership_qualifications）

4. **ENUM追加**
   - `JobChangeIntent`（active, considering, if_good, not_thinking）

## 実装時の注意点

1. **community.code === 'other' の制約**
   - 顧客のコミュニティに紐づけない
   - 管理者の権限スコープに紐づけない
   - アプリケーション層で制御

2. **subEmailsの制約**
   - 最大3件の制約はアプリケーション層で実装

3. **アンケート固定設問の出し分け**
   - afterParty: event.hasAfterParty === true の場合のみ
   - membership: ベンチャー監査役の会イベント かつ 非会員の場合のみ

4. **マスターテーブルの表示順**
   - 全マスターテーブルに sort_order カラムを持ち、フォームのセレクトボックス等での表示順を制御
