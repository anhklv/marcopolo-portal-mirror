# 初期実装案

## メール送信フロー（初期版）

### 目的

- 管理者に「正しい状態」を見せる
- 途中失敗が起きても「どこまで送れたか」を把握できるようにする
- 初期は仕組みを簡単に保ち、将来拡張可能にする

---

### 基本フロー

1. 管理画面で「メール送信開始」ボタンを押す
2. Next.js API が即時レスポンス
   - 画面表示：「送信を開始しました」
3. サーバー側でバックグラウンド送信開始
4. 1通ずつメール送信
5. 各送信結果を DB に記録
6. 全件処理後、ステータスが「完了」になる

---

### 管理画面の状態表示（想定）

- 未送信
- 送信中（120 / 300）
- 完了（300 / 300）
- 失敗あり（再送可能）

※ 「完了しました」は **送信開始完了**を意味する  
※ 「送信完了」は別ステータスで表現する

### 実装方針（初期）

- Cloud Tasks を使用して送信ジョブをキュー化
- API で送信処理を同期的に全部やらない
- Cloud Tasks でバックグラウンド送信を実行

#### 擬似コード（概念）

```ts
// POST /api/send-mails
const targets = await getTargets(eventId);

for (const user of targets) {
  await createCloudTask({
    url: '/api/send-mail-worker',
    payload: { eventId, userId: user.id }
  });
}

return { ok: true };

// Cloud Tasks から呼ばれるワーカー
// POST /api/send-mail-worker
async function sendMailWorker(eventId, userId) {
  try {
    await sendMail(user);
    await updateMailLog(user, "sent");
  } catch (e) {
    await updateMailLog(user, "failed", e);
  }
}
```

---

### なぜ Promise.all しないか

- 途中失敗時の把握が難しい
- リトライ単位を制御しにくい
- 今回の規模（300通）では速度より確実性を優先

## DB設計（仮設計・最低限）

### users（顧客）

- id
- email
- name（任意）
- created_at

### events（イベント）

- id
- title
- start_at
- end_at
- created_at

### mail_logs（送信ログ）

- id
- event_id
- user_id（または email）
- mail_type（invite / reminder / survey）
- status（pending / sent / failed）
- provider_message_id（任意）
- error_message（任意）
- sent_at
- created_at

### tokens（参加/不参加用リンク）

- id
- event_id
- user_id（または email）
- token
- purpose（rsvp_yes / rsvp_no）
- expires_at（任意）
- created_at

## アンケート設計（Google フォーム）

### 方針

- 自前アンケートは作らない
- Google フォームを利用
- メールに URL を貼るだけ

---

### Google フォーム設定

- Google アカウント不要
- 回答回数制限：OFF
- メール自動収集：OFF
- ドメイン制限：OFF

---

### システムとの紐づけ方針

- 厳密な自動連携は行わない
- メールアドレスで突合する

### 事前入力（プリフィル）

```
https://forms.gle/xxxx?entry.12345=user@example.com
```

- 回答者は入力不要
- 表記揺れを防止
- 回答は Google スプレッドシートで確認
- 必要に応じて DB と突合（人手前提）

---

## 設計思想（最重要）

- 平時は完全に静か
- イベント時だけ起動
- 完璧な自動化を目指さない
- 管理者が把握できる状態を最優先
- 小規模・低アクセス前提で疲れない構成

---

## 将来拡張（必要になったら）

### アンケート自前実装

- 回答の自動取り込み
- 厳密なイベント・ユーザー紐づけが必要になった場合のみ検討

---

## 最終結論

- Next.js（SSR）を Cloud Run で運用
- DB は Cloud SQL（設計は仮）
- メール送信は Resend（テンプレートは自前）
- バックグラウンド処理は Cloud Tasks を使用
- アンケートは Google フォーム
