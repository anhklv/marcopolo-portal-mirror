# 開発手順（2026/01/28）

## 前提

| 項目 | 決定事項 |
|------|---------|
| 技術スタック | Next.js 16 + Tailwind CSS v4 + shadcn/ui (new-york) |
| DB | Supabase (PostgreSQL) |
| ORM | Prisma |
| 認証 | NextAuth.js |
| メール配信 | Resend |
| 非同期処理 | Inngest |
| エラー監視 | Sentry |
| デプロイ | Vercel |
| 開発体制 | 自分 + AI |
| ブランドカラー | 未定（後から globals.css の CSS 変数を差し替えるだけで反映可能） |

## 方針

- mockup/ でデザインの方向性をクライアントに確認した後、product/ をゼロから構築する
- デザインは早い段階でクライアントに見せて承認を得る
- テーマ変数（globals.css）やレイアウトコンポーネントの整備は product/ で行う。mockup/ では見た目の方向性確認のみ
- Service 層は当面不要。必要になってから追加する
- 設計の詳細は [04-Next.jsベストプラクティス設計案_20260128.md](nextjs設計案/04-Next.jsベストプラクティス設計案_20260128.md) を参照

---

## フェーズ0: 設計 + デザイン方向性確認

1. **DB設計（テーブル設計）**
   - mockup/ の型定義（`lib/types/`）とモックデータ（`lib/data/mock.ts`）を元にテーブルを設計
   - Prisma スキーマとして定義

2. **権限設計**
   - super（特権管理者）/ community_admin（コミュニティ管理者）のアクセス制御ルール整理
   - ページ単位・データ単位の認可ルールを明文化

3. **mockup/ の主要画面のデザインを整える**
   - 一覧ページ（顧客一覧）、フォームページ（顧客新規作成）、詳細ページ（顧客詳細）の3画面
   - ボタン variant、余白、フォーム構造など見た目の統一
   - 全ページの統一やテーマ変数の整理はしない（方向性の確認が目的）

4. **→ クライアントにデザインの方向性を見せて承認を得る**

---

## フェーズ1: product/ の土台構築

5. **product/ の Next.js プロジェクト初期化**
   - Tailwind CSS v4 + shadcn/ui セットアップ
   - globals.css にテーマ変数を配置（デフォルト値で開始）

6. **Prisma + Supabase セットアップ**
   - フェーズ0 の DB 設計を元にスキーマ定義
   - マイグレーション実行

7. **NextAuth.js + 権限管理セットアップ**
   - ログイン / ログアウトの基本フロー
   - super / community_admin のロール管理
   - 権限チェック用のミドルウェア or フック

8. **レイアウトコンポーネントの作成**
   - 承認されたデザインを元に FormPage / ListPage / DetailPage を構築
   - コンポーネント使用ルール（ボタン variant、余白、ラベル）をコードで強制

---

## フェーズ2: 管理画面 CRUD

9. **顧客管理**
   - 一覧（検索・フィルタリング）
   - 新規登録
   - 詳細表示（参加イベント履歴含む）
   - 編集・削除
   - CSV エクスポート

10. **管理者管理**
   - 一覧
   - 新規登録
   - 編集・削除
   - パスワード変更

11. **イベント管理**
    - 一覧（検索・フィルタリング）
    - 作成（2ステップ）
    - 詳細表示（参加者一覧含む）
    - 編集・削除・一時停止

---

## フェーズ3: メール・公開側

12. **Resend + Inngest セットアップ**
    - メール送信基盤の構築
    - 非同期処理の設定

13. **案内メール送信**
    - 3ステップウィザード（宛先選択 → プレビュー → 送信）
    - 個別トークン付き URL の自動生成
    - テスト送信機能

14. **公開側: RSVP 回答フォーム**
    - トークン認証（ログイン不要）
    - 参加 / 不参加 / オンライン参加の選択
    - 懇親会参加意思（オンライン参加者は非表示）

15. **リマインドメール送信**
    - 未回答者の自動抽出
    - 3ステップウィザード

16. **アンケート作成・管理**
    - カスタム設問の作成・編集
    - 固定設問（懇親会評価、参加意向、入会意向）
    - 会員 / 非会員での出し分けロジック

17. **アンケートメール送信**
    - 参加者への回答依頼
    - 3ステップウィザード

18. **公開側: アンケート回答フォーム**
    - トークン認証（ログイン不要）
    - カスタム設問（5段階評価 + 理由入力）
    - 固定設問の出し分け

19. **アンケート結果集計**
    - 回答数の集計・一覧表示

---

## フェーズ4: 仕上げ

20. **CSV インポート**
    - 初期データ移行用の簡易実装

21. **ブランドカラー確定 → テーマ反映**
    - globals.css の CSS 変数を差し替え

22. **ステージング環境構築**
    - Vercel プレビュー環境
    - Supabase Free（500MB）

23. **E2E テスト**
    - 認証フロー
    - 顧客管理の CRUD
    - イベント管理の CRUD
    - メール送信フロー
    - 公開側フォームの回答フロー

24. **Sentry セットアップ**
    - エラー監視の導入

25. **本番デプロイ**
    - Vercel 本番環境
    - ドメイン設定（.jp）
    - 環境変数の設定
